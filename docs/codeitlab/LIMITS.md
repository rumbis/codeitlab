# What CodeItLab does not do

Every feature page says what it cannot do where the user meets it. This page
collects those statements in one place so the claim can be checked instead of
trusted. If a limit here disagrees with the app, the app is wrong and this page
should be fixed with it.

## Blocked work, with the reason

| Item                                     | Why it is not done                                                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Telegram bots                            | Needs a bot token from the user; the code path is local web chat only until one is configured                                                                                                                                                                                                                                                                                                                    |
| Per-bot schedules and shared threads     | Follows Telegram and the vault wiring; not started rather than half-built                                                                                                                                                                                                                                                                                                                                        |
| Sandbox health (G4)                      | Health answers "can this machine run a sandbox" with real checks: a version command, then the question the version cannot answer (Tart's VM list, the Docker/Podman daemon, WSL's distribution list). Windows prints that list as UTF-16LE, so the NULs are stripped and an empty list fails with `wsl --install -d Ubuntu` — the CLI alone runs nothing. It still proves readiness, never that a machine exists |
| Tart sandbox machine (G4)                | Start backgrounds `tart run` with nohup and then believes `tart list`, because the spawn's exit code is not proof of a boot; if the OS kills the VM the badge returns to `stopped`. The VM has no file sharing into the app, so a turn still cannot run inside it                                                                                                                                                |
| Sandbox agent tools (G4)                 | `cil_sandbox_status` and `cil_sandbox_run` work, but no turn is routed into the machine and `create`/`start`/`stop`/`remove` are deliberately not tools: consent is the human's. The tools run inside the app's own MCP server, so a provider that bypasses it (custom CLI, no MCP) cannot reach the sandbox                                                                                                     |
| Sandbox copy-in (G4)                     | `cil_sandbox_sync` copies tracked files into `/work`, one way: nothing comes back, gitignored files stay home, caps 500 files / 8 MB, and a re-sync never deletes files dropped from HEAD. Containers are tested; the Tart path pipes the archive through `tart exec` stdin, unprovable without a Tart CLI. `create`/`start`/`stop`/`remove` are not tools: consent is the human's                               |
| Sandbox images                           | The app never pulls a Tart image (a macOS image is tens of GB, so that is the user's decision and their `tart pull`). Containers may pull their image during create, and the confirm group names it                                                                                                                                                                                                              |
| Stripe Connect sandbox                   | Needs `sk_test_…` and `acct_…` credentials; the escrow code exists but is unverified against a real sandbox                                                                                                                                                                                                                                                                                                      |
| Hosted deployments                       | `app.codeitlab.com` answers nothing and `codeitlab.com/market` returns 404: the PWA and the marketplace are code you run, not a URL you visit. The pairing link and marketing site point at the intended origin                                                                                                                                                                                                  |
| Marketplace browser e2e                  | Needs the separate marketplace deployment running; there is no fake of it in the test suite                                                                                                                                                                                                                                                                                                                      |
| Lighthouse PWA score                     | Needs a production build served over HTTPS on a quiet machine                                                                                                                                                                                                                                                                                                                                                    |
| Desktop cold start row in PERFORMANCE.md | Needs the app fully closed and a quiet machine, otherwise the second instance just focuses the first                                                                                                                                                                                                                                                                                                             |

## Custom model endpoints

An OpenAI-compatible endpoint added under **Settings → CodeItLab → Models** is
**registered, probed and listed, not dispatched to**. CodeItLab can validate its
base URL, fetch `/models` on the server with the key from an environment
variable, and show the result next to the built-in providers — but a coding turn
still runs through a provider harness (Codex, Claude, Cursor, Grok, OpenCode,
Antigravity, an ACP agent), because an OpenAI-compatible endpoint has no agent
runtime behind it. The Models page says so where the endpoint is added rather
than letting a saved endpoint look like a working turn target.

Discovery has its own bounds: the model list is capped at
`MODEL_ENDPOINT_MODEL_LIMIT` (2000) so an aggregator advertising thousands of
models cannot stall the page, plain HTTP is refused for public hosts because the
bearer token rides on every request, and a probe that cannot reach the endpoint
is reported as unreachable instead of as an empty model list. See
[MODELS-AND-QUOTA.md](./MODELS-AND-QUOTA.md).

## Naming

The product name is `CodeItLab`; `cil` is the short id for state and namespaces we own,
and `codeitlab` is the id other tools see (npm package, release archives, CLI binary,
bundle id). [RENAME.md](./RENAME.md) lists which surface uses which. The hosted origins
(`app.`, `relay.`, `ingest.`) are placeholders on two domains and must point at a domain
CodeItLab owns before a public release.

## Telemetry

CodeItLab operates no telemetry endpoint of its own and adds no product events of its
own. It inherits the upstream server's product usage events: they go to
`ingest.codeitlab.dev`, which forwards them to PostHog, and relay connection traces go to
Axiom. Prompts, responses, file contents, authentication tokens and conversation IDs
are not in those events. Set `CIL_TELEMETRY_ENABLED=false` before starting the server
to turn both off; the desktop app reads it from your shell profile. The full account
is in [docs/user/telemetry.md](../user/telemetry.md).

That is a statement about this code, not a promise about the other harnesses or
providers you connect: they keep their own behaviour and their own policies.

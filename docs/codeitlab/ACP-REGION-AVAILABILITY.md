# ACP agents — region availability

Feeds the provider wizard's availability warning: before we install or advertise an ACP registry agent, we want to know whether the vendor serves the user's country. Verified on **2026-10-24** against each vendor's own pages.

**Method.** For each of the 43 registry ids we recorded (a) how the user signs up or signs in, and (b) any country/region statement the vendor publishes. Where a vendor publishes no country list, the row says so and names the page we checked — that is a finding, not a gap. A vendor that only publishes a sanctions/export-control clause is marked `partial`: it tells us the vendor is not worldwide, but not which countries are allowed.

**Confidence**

- `verified` — vendor publishes an explicit country list or an explicit restricted-region statement that we read.
- `partial` — only a generic sanctions/embargo clause, or a regional product split, was found.
- `unverified` — no statement found, or the vendor site/docs were unreachable.

## Notes

**The Cyprus case (MiniMax).** The only region statement MiniMax publishes is the "Export Controls and Sanctions" section of its Open Platform Terms of Service, which lists comprehensively sanctioned regions — Iran, Cuba, North Korea, Syria, the Crimea/Sevastopol region, and the so-called DPR/LPR — and nothing about the EU or Cyprus ([terms](https://platform.minimax.io/docs/guides/terms-of-service.md)). MiniMax Code itself is documented as "sign in with the same account as your M Plan subscription" with no geography mentioned ([MiniMax Code docs](https://platform.minimax.io/docs/m-plan/minimax-code)). So the failure a Cyprus user sees is **not explained by any published policy**: either an undocumented geo-block on the sign-up/payment flow, or a phone/identity-verification restriction. Treat it as a real-world block, mark it UNVERIFIED in the UI, and do not claim "available worldwide". The same caution applies to the Chinese domain `minimaxi.com`, which is a separate service from `minimax.io`; we did not find a public page describing which one a given country may use.

**Vendors that publish a real allow-list (the only fully trustworthy rows).** Anthropic (Claude Code) and OpenAI (Codex) both publish supported-country lists that include Cyprus, Google publishes an Antigravity allow-list that includes Cyprus and a separate Gemini API available-regions list that includes the Republic of Cyprus, and GitHub publishes trade-control restrictions. Everything else is either a sanctions-only clause (Cursor, Snowflake, JetBrains, MiniMax) or silence.

**Consequence for the wizard.** Country data is only reliable enough to _warn_, not to _block_. Recommended behaviour: show an inline notice for the four verified vendors when the user's region is outside the list; for everyone else, install normally and surface the vendor's own error rather than pre-emptively hiding the agent. A hard block on `unverified` rows would wrongly exclude MiniMax, Qoder, Kimi and the rest from most of the world.

**Changes worth re-checking.** Google moved Gemini CLI's unpaid and AI Pro users to Antigravity CLI on 2026-06-18, and Antigravity now carries its own explicit country list, so the `gemini` and `antigravity-acp` rows can diverge — do not inherit one from the other. Qoder documents a separate International and China product split but publishes no eligibility rules. CodeBuddy has the same `.cn` / `.ai` split with no published rules. Kimi CLI is archived and replaced by Kimi Code CLI, whose docs still publish no geography.
